# Arbox API docs: deep links per operation

Research note. Goal: a stable deep link for each of the 65 operations (and the 47 report names) in the official docs at https://arboxserver.arboxapp.com/docs/api.

## Verdict

**VERIFIED in headless Chrome** on 5 operation links (with a negative control) and 1 schema link. Pattern below.

## URL pattern

- Operation: `https://arboxserver.arboxapp.com/docs/api#/operations/<operationId>`
- Schema: `https://arboxserver.arboxapp.com/docs/api#/schemas/<SchemaName>`
- `<operationId>` is the raw `operationId` from the spec, **not** slugified and **not** method+path. Spaces become `%20` when encoded (`Create New Lead` -> `Create%20New%20Lead`). Use `encodeURIComponent` on the id.
- No project prefix in hash mode. The hash is the whole route.

## Slug rule (source)

Source tag: there is no `v8.4.2` git tag upstream. The release commit is `38f79d36670b007494b6646f4f55231fce77c29b` (the `gitHead` of `@stoplight/elements@8.4.2` on npm). Links below point at that commit.

1. Operations get `/operations/${iid}` when the operation has an `iid`. `iid` is the raw `operationId`. Code: [`packages/elements/src/utils/oas/index.ts` L110-L118](https://github.com/stoplightio/elements/blob/38f79d36670b007494b6646f4f55231fce77c29b/packages/elements/src/utils/oas/index.ts#L110-L118). The `iid` assignment is in `@stoplight/http-spec@7.1.0`, `oas/operation.js` line 90: `iid: obj.operationId`.
2. Fallback without `iid`: `uri.replace(path, slugify(path))`, where `slugify` replaces `/`, `{`, `}` and whitespace with `-` ([`packages/elements-core/src/utils/string.ts`](https://github.com/stoplightio/elements/blob/38f79d36670b007494b6646f4f55231fce77c29b/packages/elements-core/src/utils/string.ts)). This fallback does not apply here because every operation has an `operationId`.
3. Schemas: `components/schemas/X` is rewritten to `schemas/X` by `OAS_MODEL_REGEXP` ([L43](https://github.com/stoplightio/elements/blob/38f79d36670b007494b6646f4f55231fce77c29b/packages/elements/src/utils/oas/index.ts#L43), [L154](https://github.com/stoplightio/elements/blob/38f79d36670b007494b6646f4f55231fce77c29b/packages/elements/src/utils/oas/index.ts#L154)).
4. Hash router: the TOC makes slugs absolute (`#/...`) when the router is `hash` ([TableOfContents.tsx L54-L56](https://github.com/stoplightio/elements/blob/38f79d36670b007494b6646f4f55231fce77c29b/packages/elements-core/src/components/TableOfContents/TableOfContents.tsx#L54-L56)). The served page's own TOC hrefs use the raw id with spaces (for example `#/operations/Get All Leads#Request`), which matches the rule.

Least-sure items, resolved:
- Slug uses **operationId**, not method+path (the `iid` branch wins whenever `operationId` exists).
- Hash has **no project prefix**. Confirmed by the browser dumps below.

## Browser evidence

Method: headless Google Chrome (local app build), `--headless=new --virtual-time-budget=15000 --dump-dom <url>`. The claude-in-chrome extension was not connected, and `agent-browser` is not installed, so headless Chrome was the browser used. Each check reads the rendered `<h1>`.

| # | Link tested | Method / path | Expected heading | Rendered `<h1>` | Result |
|---|---|---|---|---|---|
| 1 | `#/operations/Create%20New%20Lead` | POST `/v3/leads` | Create New Lead | Create New Lead | PASS |
| 2 | `#/operations/Get%20All%20Leads` | GET `/v3/leads` | Get All Leads | Get All Leads | PASS |
| 3 | `#/operations/Mark%20Task%20as%20Completed` | POST `/v3/tasks/markAsCompleted/{task_id}` (path param) | Mark Task as Completed | Mark Task as Completed | PASS |
| 4 | `#/operations/Cancel%20Trial%20Booking` | DELETE `/v3/schedule/booking/trial` | Cancel Trial Booking | Cancel Trial Booking | PASS |
| 5 | `#/operations/Create%20or%20update%20injury` | PATCH `/v3/users/injury` (lowercase words, spaces) | Create or update injury | Create or update injury | PASS |
| 6 | `#/schemas/BookForTrialClassRequest` | schema | BookForTrialClassRequest | BookForTrialClassRequest | PASS |
| N | `#/operations/Nonexistent%20Op%20Xyz` | none (negative control) | not an operation | `Arbox API` (service root) | Falls back to root, so the PASS checks are meaningful |

Caveats:
- No operationId in the spec contains punctuation. The only "odd characters" are spaces and mixed case. Test 5 covers the odd case.
- These operations have no `summary`, so the heading is the operationId itself. The heading check confirms the id, not the summary text.
- Only 5 of 65 operations were opened in a browser. The other 60 use the same generated pattern, not individual browser checks.
- Headless dump, not an interactive session. Clicking a TOC item was not tested.
